# 路线图

[返回首页](../README.md) · [架构与边界](architecture.md) · [实施计划与验收](implementation-plan.md)

目标是让 Windows 单机与多机用户可靠地进入所需 dsh 实例：单机先可用，多机再扩展；操作前知道影响，操作后能看懂结果并恢复。路线图说明优先级，不代替已完成证据。

## 当前能力与边界

本轮补齐了逐实例结果、只读计划、版本固定、配置上下文与维护、缓存竞态、进程所有权及完整资源打包，并把启动器、后端和 UI 按职责拆分。任务结果、操作范围、恢复入口与键盘语义已有离线检查。

这些结果不是生产环境验收：真实 SSH/systemd、浏览器外观和干净 Windows 首次启动仍需现场验证。一个远端用户账户只管理一个服务；本地多个实例共享运行时，升级需先明确影响范围，不能承诺原子回滚。

具体限制与恢复路径见[日常操作](operations.md)、[配置参考](configuration.md)及[安全与隐私](security.md)。历史“已修复”记录保存在[档案](archive/README.md)，不作为当前支持保证。

## 本轮顺序

阶段、固定决策、接口与复选框只维护在 [implementation-plan](implementation-plan.md)，这里不复制一份进度表。

| 阶段 | 用户应得到什么 | 验收重点 |
| --- | --- | --- |
| 0：文档基线 | 能找到上手、配置、操作与安全说明，历史与当前分开 | 导航、内部链接、语法结构、历史原文保留 |
| 1：可信交付 | 明确的安装范围、遵守 pin 的升级、真实的成功/失败 | 逐实例结果、非零失败、所有权、缓存竞态、统一上下文、独立 EXE |
| 2：可维护性 | 修复一处不会让 CLI 与面板分叉 | 职责拆分、可注入替身、离线回归、打包与文档门禁 |
| 3：易用性 | 看得懂预览，能维护实例，操作结果不会一闪而过 | 单机引导、编辑/停用/移除、中文错误、部分成功、焦点与窄屏 |

`plan`、`edit`、`remove`、`ssh-hosts` 及对应 API 已实现；验收以 implementation-plan 中的实际命令与结果为准，不仅以存在入口或示例判定。

## 后续候选，不是本轮承诺

- 实例与工作目录导航、上次入口记忆；会话跳转只依赖上游公开支持的接口。
- 更细的端口冲突说明、远端配置变更引导、只通知不升级的检查策略。
- 更完善的健康摘要、团队引导；跨平台桌面仅在有需求和可验证方案时评估。

历史提出过会话导出、只读分享、专用初始化命令和额外更新通道；本轮不实施，也不承诺交付时间。分享涉及数据脱敏与上游能力，不能绕开本地安全边界。

## 明确不做

- 不开放 dsh 公网监听，不增加托管控制面或遥测。
- 不复制、解析或依赖 dsh 私有会话存储格式，也不另造一个重复的会话浏览器。
- 不把密码、私钥或 API key 写进实例配置；同时如实说明运行认证信息仍会落盘。
- 不提供原子升级回滚保证，不在未确认共享运行时影响时强行升级。
- 不为本轮引入大型框架、第三方运行时依赖或多用户服务器托管模型。

## 完成如何判定

只有实际验证记录才能把目标改为当前能力。静态检查不能替代真实 Windows、SSH 或浏览器验收；未执行的场景必须标为未验证。

当前文档与实现同步维护，完成项必须附实际验证；归档正文保留原貌，不随实现进度改写。
